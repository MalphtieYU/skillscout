# Vague Task

**User:** I want to make a project. Recommend plugins.

## SkillScout Recommendation

### 1. My Read of Your Task

You want to begin a project, but the deliverable, source material, and required actions are not yet known.

**Confidence:** Low Confidence

### 2. Tooling Decision

**Plugins Optional.** It is too early to recommend a stack responsibly. Start with native planning; tools may become useful for a real repository, design source, file format, or external service after the project is defined.

### 3. Why This Decision

Tools could help later, but recommending them now would be guesswork and may create unnecessary setup or permissions. The right choice depends on what you are building, what information already exists, and whether Codex must act on an external system.

### 4. Recommended Minimal Setup

| Tool / Plugin / Skill | Priority | Why it helps | Use it when | Skip it when | Plain-language explanation | 中文解释 |
| --- | --- | --- | --- | --- | --- | --- |
| Codex Native Planning | Required | Clarifies scope first | The project is not defined | A concrete external need is known | Turn an idea into an actionable brief | 先把项目目标说清楚，再决定工具 |

Possible future directions: GitHub for a real repository, Figma for an existing design source, or file/data tools for real structured files.

### 5. Tools You Should Not Use for This Task

Do not install a broad collection of plugins yet. GitHub, Figma, MCP, and Automation have no clear job until the deliverable is known.

### 6. Better Workflow

1. Define the final deliverable.
2. Identify whether you need current information, files, or an external account.
3. Start a native outline or prototype.
4. Add one tool only when a concrete need appears.

### 7. Copy-ready Codex Prompt

```text
Help me turn this project idea into a clear brief. First identify the final deliverable, target users, existing files or services, and the first small milestone. Recommend tools only if a concrete need appears.
```

### 8. Ask These First if Unclear

1. What final deliverable do you want?
2. Do you need current web information or private files?
3. Do you need Codex to act in a repository, design tool, cloud drive, or another service?
